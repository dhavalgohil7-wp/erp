1. OVERVIEW
================================================================================

This document describes the complete process of migrating the School ERP
system's database backend from PostgreSQL to MySQL. The backend is built
on Laravel 12 (PHP 8.2+) and runs locally on WAMP64. The frontend is a
React (Vite) application and was not affected.

All migrations ran successfully against MySQL 9.1.0 running under WAMP64
after applying the fixes documented below.

3. MOTIVATION FOR MIGRATION
================================================================================

  * The project is hosted on WAMP64 which ships with MySQL (not PostgreSQL).
  * Running PostgreSQL as a separate service alongside WAMP adds unnecessary
    complexity for local development.
  * MySQL is natively supported by WAMP, making setup simpler for the team.
  * Laravel 12 supports MySQL out-of-the-box with zero extra packages.
  * No PostgreSQL-specific column types (jsonb, uuid, tsvector, etc.) were
    used in any migrations -- making the switch straightforward.

------------------------------------------------------------------------------
5.3  SET INNODB ENGINE  --  backend/config/database.php
------------------------------------------------------------------------------

  BEFORE:
    'mysql' => [
        ...
        'engine' => null,       // uses server's default engine
        ...
    ],

  AFTER:
    'mysql' => [
        ...
        'engine' => 'InnoDB',   // explicitly force InnoDB
        ...
    ],

  Reason:
    WAMP's MySQL 9.1.0 is configured with:
      default_storage_engine = MyISAM

    MyISAM only supports index key lengths up to 1000 bytes. InnoDB supports
    up to 3072 bytes. Using utf8mb4 (4 bytes per character), a 255-char
    VARCHAR column alone uses 1020 bytes -- exceeding the MyISAM limit.

    Setting 'engine' => 'InnoDB' in Laravel's connection config causes every
    CREATE TABLE statement to include "ENGINE=InnoDB", overriding the server
    default.


------------------------------------------------------------------------------
5.4  FIX DEFAULT STRING LENGTH  --  backend/app/Providers/AppServiceProvider.php
------------------------------------------------------------------------------

  BEFORE:
    public function boot(): void
    {
        //
    }

  AFTER:
    use Illuminate\Support\Facades\Schema;

    public function boot(): void
    {
        // Fix MySQL utf8mb4 index key length limit
        Schema::defaultStringLength(191);
    }

  Reason:
    Laravel's Schema::defaultStringLength(191) tells the schema builder to
    generate VARCHAR(191) instead of the default VARCHAR(255) for all
    $table->string() calls without an explicit length.

    Calculation:
      191 characters x 4 bytes (utf8mb4) = 764 bytes
      Safely under InnoDB's limit of 3072 bytes per single column index.

    This ensures that columns used in UNIQUE indexes (e.g., users.email)
    never exceed the index size limit.


------------------------------------------------------------------------------
5.5  FIX SPATIE PERMISSION MIGRATION
     backend/database/migrations/2026_10_07_041849_create_permission_tables.php
------------------------------------------------------------------------------

  The spatie/laravel-permission package migration uses ->string()
  without explicit length. Since its closures are declared as "static",
  they do not inherit Schema::defaultStringLength() set in AppServiceProvider.
  String lengths were added explicitly.

  COLUMNS CHANGED:
    permissions table:
      ->string('name')        ->  ->string('name', 191)
      ->string('guard_name')  ->  ->string('guard_name', 191)

    roles table:
      ->string('name')        ->  ->string('name', 191)
      ->string('guard_name')  ->  ->string('guard_name', 191)

    model_has_permissions table:
      ->string('model_type')  ->  ->string('model_type', 191)

    model_has_roles table:
      ->string('model_type')  ->  ->string('model_type', 191)

  Why 191?
    The unique index on permissions is: UNIQUE(name, guard_name)
    Combined index size = 191x4 + 191x4 = 1528 bytes -- well under 3072.

7. TECHNICAL NOTES & WHY EACH FIX WAS NEEDED
================================================================================

  Issue 1: SQLSTATE[HY000] [1049] Unknown database 'school_erp'
  ---------------------------------------------------------------
  Cause : Database did not exist in MySQL yet.
  Fix   : Created it manually via MySQL CLI with utf8mb4 charset.


  Issue 2: SQLSTATE[42000] Specified key was too long; max key length 1000 bytes
  -------------------------------------------------------------------------------
  Cause : WAMP uses MyISAM as default_storage_engine.
          MyISAM max index key = 1000 bytes.
          VARCHAR(255) x utf8mb4 = 1020 bytes > 1000 bytes.
  Fix   : Forced InnoDB engine in config/database.php.
          InnoDB supports up to 3072 bytes per index key.


  Issue 3: Same key-length error on permissions table after InnoDB fix
  --------------------------------------------------------------------
  Cause : Spatie permission migration closures are declared "static".
          Static closures do not inherit Schema::defaultStringLength()
          set in AppServiceProvider::boot().
  Fix   : Explicitly passed 191 as the length argument to all string()
          columns that participate in unique indexes in that migration.


  Why utf8mb4 and not utf8?
  -------------------------
  MySQL's "utf8" is actually utf8mb3 -- it only supports BMP characters
  (U+0000 to U+FFFF). "utf8mb4" is true UTF-8 supporting all Unicode
  code points including emoji (U+10000+).
  Laravel uses utf8mb4 by default and so do we.


  No PostgreSQL-specific SQL found
  ---------------------------------
  All migrations use standard Laravel Schema Builder methods:
    id(), foreignId(), string(), text(), boolean(), date(),
    decimal(), timestamps(), unique(), etc.
  These are database-agnostic and work on MySQL without any changes.

9. ROLLBACK INSTRUCTIONS
================================================================================

  If you need to switch back to PostgreSQL, reverse the following:

  STEP 1 -- Restore .env
    DB_CONNECTION=pgsql
    DB_HOST=127.0.0.1
    DB_PORT=5432
    DB_DATABASE=school_erp
    DB_USERNAME=postgres
    DB_PASSWORD=admin   (or your actual password)

  STEP 2 -- Restore config/database.php
    'engine' => null,

  STEP 3 -- Restore AppServiceProvider.php
    Remove Schema::defaultStringLength(191) and the Schema facade import.

  STEP 4 -- Restore permission migration
    Remove the explicit (191) lengths from string() calls.

  STEP 5 -- Create PostgreSQL database
    CREATE DATABASE school_erp
      WITH ENCODING 'UTF8'
      LC_COLLATE='en_US.UTF-8'
      LC_CTYPE='en_US.UTF-8';

  STEP 6 -- Run migrations
    php artisan config:clear
    php artisan migrate --force
